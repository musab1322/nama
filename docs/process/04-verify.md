# المرحلة 4: الاختبار والتحقق

**الهدف:** إثبات أن كل متطلب معتمد يعمل، وأنه لا توجد ثغرات أو أخطاء منطقية معروفة.

## الخطوات
1. مراجعة الكود مقابل المواصفات (هل نفّذنا ما اعتُمد فقط؟).
2. اختبارات الوحدة للمنطق (المسارات، الحسابات، تحويل الحالات).
3. اختبارات قاعدة البيانات: RLS لكل جدول (مستخدم يرى بياناته فقط، ومجهول لا يرى شيئاً).
4. اختبارات التكامل للـ API مع مزوّدين وهميين (Vercel وExpo وApple وGoogle).
5. اختبارات طرف لطرف (Playwright) لكل حالة استخدام Must، بالعربية والإنجليزية وعلى عرض الجوال.
6. مراجعة أمنية: OWASP Top 10، والتحقق من توقيع الـ webhooks، وتسرّب الأسرار، والصلاحيات، وحدود الاستخدام.
7. اختبار على بيئة staging حقيقية (بموافقة) للتدفقات التي لا يمكن محاكاتها.
8. إنتاج **قائمة تحقق** لمصعب: بند لكل حالة استخدام، بخطوات يدوية بسيطة ونتيجة متوقعة.

## قواعد
- كل معيار قبول ← اختبار آلي أو بند يدوي في قائمة التحقق.
- ممنوع تعطيل أو تخطي اختبار لتمرير البوابة.
- أي خطأ يُكتشف يُسجَّل (`BUG-xxx`) مع المتطلب المتأثر.

## بوابة الخروج
- [ ] مصفوفة التتبع: كل `FR` Must ← اختبار ناجح.
- [ ] لا أخطاء حرجة أو عالية مفتوحة.
- [ ] قائمة التحقق مُسلَّمة ومُجرَّبة من مصعب.
- [ ] مصعب اعتمد صراحة.
